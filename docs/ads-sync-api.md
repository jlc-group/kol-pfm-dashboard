# การซิงก์ข้อมูลจากระบบยิงแอด → KOL Dashboard

เอกสารสำหรับทีมที่ดูแลระบบยิงแอด ใช้ส่งค่าใช้จ่ายและผลงานเข้ามาที่ dashboard

## หลักการ

- ค่ายิงแอด **ไม่แสดงตัวเลขที่ไหนเลย** ในหน้าเว็บ ใช้เป็นตัวจุดชนวนอย่างเดียว
- เมื่อค่าแอดสะสมของคลิปหนึ่งถึง **10,000 บาท** ระบบจะ **สแตมป์ผล Performance** ณ ตอนนั้นไว้ถาวร แก้ไม่ได้ ล้างไม่ได้
- ยิงเข้ามาบ่อยแค่ไหนก็ได้ ระบบจับคู่และอัปเดตให้เอง

## Endpoint

```
POST /api/ads-sync/sync
Header: X-Ads-Sync-Key: <คีย์ที่ตั้งไว้ใน .env>
Content-Type: application/json
```

ไม่ต้องล็อกอินด้วยบัญชีคน — ใช้ API key ของระบบต่อระบบ ตั้งค่าที่ `ADS_SYNC_KEY`
ในไฟล์ `server/.env` (ถ้าไม่ได้ตั้ง endpoint จะตอบ 503 = ปิดอยู่)

## รูปแบบข้อมูล

```json
{
  "rows": [
    {
      "gencode": "#pmwejiS2bv...",
      "ad_spend": 12500,
      "ad_reach": 480000,
      "views": 320000,
      "likes": 8200,
      "comments": 310,
      "saves": 450,
      "shares": 120
    }
  ]
}
```

### การจับคู่แถว

ใช้ตัวใดตัวหนึ่ง เรียงตามลำดับความแม่นยำ:

| ฟิลด์ | คำอธิบาย |
|---|---|
| `submission_id` | id ของแถวใน dashboard (แม่นที่สุด ถ้าฝั่งระบบยิงแอดเก็บไว้ได้) |
| `gencode` | Gencode ของคลิปนั้น |
| `id_post` | ID Post ของแพลตฟอร์ม |

แถวที่จับคู่ไม่ได้จะถูกส่งกลับมาในผลลัพธ์ ไม่ทำให้ทั้งชุดล้มเหลว

### ฟิลด์ที่รับ

| ฟิลด์ | ชนิด | หมายเหตุ |
|---|---|---|
| `ad_spend` | ตัวเลข | **ค่าแอดสะสม** ไม่ใช่ยอดของรอบนั้น · ระบบรับเฉพาะค่าที่มากกว่าเดิม กันข้อมูลย้อนหลังมาลบยอด |
| `ad_reach` | ตัวเลข | reach จากระบบยิงแอด |
| `views` `likes` `comments` `saves` `shares` `reposts` | ตัวเลข | ผลงานคอนเทนต์ ใช้คิด CPM/CPE และใช้ตัดสินตอนสแตมป์ |
| `source_updated_at` | ISO datetime | เวลาที่ต้นทางอัปเดต Organic metrics ระบบจะไม่รับข้อมูลที่เก่ากว่ารอบล่าสุด |

ส่งเฉพาะฟิลด์ที่มี ฟิลด์ที่ไม่ส่งมาจะไม่ถูกแตะ

## ผลลัพธ์

```json
{
  "status": "success",
  "data": { "updated": 40, "stamped": 3, "not_found": ["#abc123"], "skipped": 0 }
}
```

- `updated` — จำนวนแถวที่อัปเดตสำเร็จ
- `stamped` — จำนวนแถวที่ถูกสแตมป์ Performance ในรอบนี้
- `not_found` — คีย์ที่หาแถวที่ตรงกันไม่เจอ
- `skipped` — แถวที่ไม่ได้ส่งคีย์จับคู่มาเลย

## ข้อจำกัด

- ส่งได้ครั้งละไม่เกิน **2,000 แถว** · ขนาด body ไม่เกิน 2 MB
- คีย์ผิด → 401 · ยังไม่ได้ตั้งคีย์ที่เซิร์ฟเวอร์ → 503

## เงื่อนไขการสแตมป์

สแตมป์อัตโนมัติเมื่อ **ค่าแอดสะสม ≥ 10,000** และ **มียอดวิวแล้ว** พร้อมกัน

ถ้าค่าแอดถึงเกณฑ์แต่ยังไม่มียอดวิว ระบบจะยังไม่สแตมป์ (หน้าเว็บขึ้นว่า "รอข้อมูลผลงาน")
แล้วสแตมป์ให้ทันทีที่ข้อมูลผลงานเข้ามา — กันไม่ให้ล็อกผลว่างเปล่าไว้ถาวร

สิ่งที่เก็บไว้ในสแตมป์: วันเวลา · ค่าแอด · ยอดวิว · engagement · ER · CPM · CPE · ผลตัดสิน (Pass/Fail)

## ใครเห็นตัวเลขต้นทุนได้

| ข้อมูล | Admin | Manager | Member | Agency |
|---|---|---|---|---|
| ผล Pass / Fail | ✓ | ✓ | ✓ | ✕ |
| CPM / CPE | ✓ | ✓ | ✕ | ✕ |
| ค่ายิงแอด | ✕ (ไม่แสดงที่ไหนเลย) | ✕ | ✕ | ✕ |

CPM คำนวณจาก `(ค่าตัว + ค่าแอด) ÷ (วิว/1000)` ซึ่งถอดกลับเป็นค่าแอดได้
จึงปิดตัวเลข CPM/CPE ไม่ให้ member เห็นด้วย

## ดึงข้อมูลจาก Beauterry PFM

เซิร์ฟเวอร์ดึงข้อมูลจาก Beauterry อัตโนมัติทุก 1 ชั่วโมง โดยใช้ `id_post` ของรายการ
TikTok ที่มีใน Dashboard และจะดึงครั้งแรกหลังเปิดเซิร์ฟเวอร์ 30 วินาที
Organic metrics จาก PFM จะไม่ถูกเขียนทับเมื่อ snapshot เก่ากว่ารอบล่าสุด หรือเมื่อตัวเลข
สะสมลดลง ส่วนค่าโฆษณายังคงใช้กฎเดิมที่รับเฉพาะค่าที่เพิ่มขึ้น

ตัวแปรตั้งค่า:

| ตัวแปร | ค่าเริ่มต้น |
|---|---|
| `BEAUTERRY_PFM_SYNC_ENABLED` | `true` |
| `BEAUTERRY_PFM_BASE_URL` | `http://127.0.0.1:8202` |
| `BEAUTERRY_PFM_EXPORT_KEY` | ถ้าไม่กำหนดจะใช้ `ADS_SYNC_KEY` |
| `BEAUTERRY_PFM_SYNC_INTERVAL_SECONDS` | `3600` |
| `BEAUTERRY_PFM_SYNC_INITIAL_DELAY_SECONDS` | `30` |

สั่งดึงทันทีได้ที่ `POST /api/ads-sync/pull-beauterry` และดูรอบล่าสุดที่
`GET /api/ads-sync/beauterry-status` โดยทั้งสอง endpoint ใช้ header
`X-Ads-Sync-Key` เหมือน endpoint รับข้อมูลเดิม
